# 03. 프론트엔드 구현 지침

## 1. 구현 범위
표준 HTML, CSS, Vanilla JavaScript만 사용한다. 별도 프레임워크 도입은 승인 없이 하지 않는다. 화면은 `public/index.html`, 스타일은 `public/css/styles.css`, 동작은 `public/js/`의 ES Module로 분리한다.

## 2. HTML 구조
- 시맨틱 요소: `header`, `main`, `section`, `form`, `article`, `footer`.
- 날짜 입력: `<input type="date">`, 과거 날짜 제한.
- 출발 위치: 텍스트 입력(주소/지역명) 및 선택적 위치 권한 버튼.
- 검색: 제출 버튼 한 개로 동작.
- 추천/결과 영역: 검색 전에는 안내 문구, 검색 후 데이터 렌더링.
- 예약 안내: `role="status"` 또는 적절한 dialog/alert 패턴.

## 3. JavaScript 모듈 책임
- `app.js`: 앱 초기화, 이벤트 연결, 상태 관리.
- `api.js`: 백엔드 API 호출, HTTP 오류 정규화.
- `render.js`: 결과 카드와 추천 카드 렌더링.
- `validation.js`: 날짜·위치 입력 검증.
모듈 수가 과도해지지 않게 실제 코드 규모에 맞춰 조정한다.

## 4. 검색 요청
`POST /api/search`에 JSON으로 전달한다.
```json
{
  "date": "2026-11-20",
  "origin": {
    "address": "사용자가 입력한 출발지",
    "latitude": null,
    "longitude": null
  }
}
```
주소를 좌표로 변환하는 기능은 지오코딩 공급자 연동이 완료된 경우에만 사용한다. 미연동 상태에서 주소를 임의 좌표로 바꾸지 않는다.

## 5. 화면 상태 모델
`idle`, `loading`, `success`, `empty`, `partial_error`, `error` 상태를 명시적으로 관리한다.
- 검색 시작: 이전 결과와 오류 상태를 정리하고 `loading`.
- 성공: 응답의 날짜가 현재 검색 날짜와 일치하는지 확인 후 렌더링.
- 결과 없음: `empty`.
- 일부 공급자 오류: 반환된 데이터는 표시하고 `partial_error`.
- 요청 실패: `error`와 재시도 동작.

중복 클릭을 막기 위해 요청 중 검색 버튼을 비활성화한다. 요청 완료 시 반드시 원상 복구한다.

## 6. 안전한 렌더링
- 외부 데이터는 `innerHTML` 문자열 결합으로 직접 삽입하지 않는다.
- `document.createElement`, `textContent`, 안전한 속성 설정을 사용한다.
- URL 링크를 표시한다면 `https` 및 허용 도메인 검증을 적용한다.
- 가격·강수확률은 숫자 여부를 확인한 뒤 포맷한다.
- null 값은 `정보 없음` 또는 `—`로 표시한다.
- 서버 오류 원문을 그대로 화면에 출력하지 않는다.

## 7. 위치 권한
- 위치 권한은 사용자가 버튼을 누른 경우에만 요청한다.
- 거부·시간 초과·지원하지 않는 브라우저 상황을 각각 안내한다.
- 위치 좌표를 서버로 보내는 목적을 요청 전에 설명한다.
- 위치를 입력하지 않아도 날짜 검색은 가능해야 한다.
- 사용자가 위치를 지우면 이전 좌표를 재사용하지 않는다.

## 8. 예약하기 버튼 동작
버튼 클릭 시 서버 예약 API를 호출하지 않는다. 다음과 같은 안내를 화면에 표시한다.
`현재 데모에서는 실제 예약을 지원하지 않습니다. 골프장 공식 예약 채널을 이용해 주세요.`
이 버튼은 `예약 요청`, `예약 완료` 등으로 상태가 바뀌면 안 된다.

## 9. 프론트엔드 검증
- 날짜 미입력 시 검색 불가 및 안내.
- 과거 날짜 차단.
- API 로딩 중 중복 요청 방지.
- 빈 배열·null·부분 오류 렌더링.
- 특수문자/HTML 입력이 스크립트로 실행되지 않음.
- 320px, 360px, 768px, 1280px 폭에서 확인.
- 키보드만으로 날짜 선택·검색·예약 안내 확인 가능.
