# 06. 날씨·추천 AI·배포·테스트 지침

## 1. 날씨 연동
- 골프장 위도·경도와 사용자가 선택한 날짜로 날씨 공급자를 조회한다.
- 공급자 공식 문서에서 예보 가능 기간, 시간 단위/일 단위 필드, 강수확률 정의, 단위를 확인한다.
- 선택 날짜가 예보 가능 기간을 벗어나면 `out_of_range`를 반환하고 `예보 제공 기간이 아닙니다`로 표시한다.
- 공급자가 강수확률을 0~1 비율로 주는지 0~100 숫자로 주는지 확인한 뒤 내부 0~100 정수로 정규화한다.
- 값이 null이면 0%로 바꾸지 않는다.
- 하루 예보를 표시할 때 시간대별 강수확률 중 어떤 값을 쓸지 정책을 정한다. 예: 라운딩 예정 시간대가 정해지지 않았다면 일 단위 대표값이 있는 경우만 사용하고, 없으면 `시간대별 예보`로 안내한다.
- 날씨 조회 시각과 출처를 보관한다.

## 2. 거리 계산
- 골프장 좌표와 사용자 출발 좌표가 모두 있을 때만 계산한다.
- 도로 이동 거리가 아닌 직선거리(Haversine)인 경우 `직선거리 약 N km`로 표기한다.
- 도로 거리·이동 시간은 지도/경로 API를 별도로 연결한 경우에만 제공한다.
- 출발 주소를 입력했지만 지오코딩을 연결하지 않았다면 거리 계산을 하지 않는다.
- 좌표가 없으면 해당 후보의 거리 점수를 null로 둔다.

## 3. 추천 선정 로직
추천 후보 선정은 서버의 결정론적 규칙으로 처리한다. AI가 사실 데이터를 추정하지 못하게 한다.

권장 기본 정책(초기값이며 코드 상수로 관리):
1. 검색 대상 중 골프장 정보가 유효한 후보만 수집.
2. 확인된 예약 가능 정보가 있다면 사용자의 날짜 조건에 맞는 후보를 우선하되, 예약 정보 미연동 시 예약 가능 후보라고 단정하지 않는다.
3. 거리 데이터가 존재하면 가까운 후보에 높은 점수를 준다.
4. 날씨 데이터가 존재하면 비 예보가 낮고 기상 조건이 양호한 후보에 높은 점수를 준다.
5. 데이터가 없는 항목은 중립 또는 미적용으로 처리하고, 결측을 좋은 점수로 보상하지 않는다.
6. 점수와 사용한 근거를 함께 반환하고 상위 최대 3곳을 선택한다.

추천 점수 가중치(예시, 제품 테스트 후 조정):
- 거리 50%
- 날씨 50%
가중치는 실제 데이터가 있는 항목만 재정규화한다. 거리 또는 날씨가 전혀 없으면 존재하는 기준만 적용하고 사용자에게 적용된 기준을 밝힌다. 예약 가능 여부가 미확인인 후보는 `예약 가능` 추천으로 표현하지 않는다.

## 4. OpenAI 프롬프트 가이드
AI 입력에는 서버에서 선택한 최대 3개 후보의 확인된 사실과 계산된 근거만 포함한다. 사용자 위치 원문, 비밀 키, 불필요한 개인정보는 보내지 않는다.

예시 지시:
- 제공된 데이터만 사용해 한국어 추천 사유를 작성한다.
- 가격, 티타임, 강수확률, 거리 수치를 새로 만들거나 수정하지 않는다.
- 누락된 정보는 언급하지 않거나 `정보 확인 필요`라고 쓴다.
- 예약 가능 여부를 추정하지 않는다.
- 후보 순서와 골프장 이름을 변경하지 않는다.
- 골프장별 추천 사유는 1~2문장, 최대 80자 정도로 작성한다.
- JSON 응답 형식과 필드 타입을 검증한다.

AI가 실패해도 추천 결과와 근거 숫자는 규칙 기반 결과를 그대로 유지한다.

## 5. 배포(Vercel)
1. Git 저장소에 코드를 커밋한다.
2. Vercel에서 저장소를 연결한다.
3. 프로젝트의 빌드/출력 설정을 실제 폴더 구조에 맞게 지정한다.
4. 환경변수를 Development/Preview/Production 환경별로 등록한다.
5. Supabase URL·키, OpenAI 키, 날씨/골프장 공급자 키를 필요한 것만 등록한다.
6. Preview 배포에서 검색·오류·반응형을 검증한다.
7. Production 배포 후 로그와 API 응답을 확인한다.

`vercel.json`을 추가해야 한다면 실제 라우팅 구조와 Vercel 최신 설정을 확인한 뒤 작성한다. 존재하지 않는 API 키나 공급자 엔드포인트를 가정하지 않는다.

## 6. 테스트 계획
### 단위 테스트
- 날짜 검증(오늘, 미래, 과거, 잘못된 형식).
- 위도·경도 범위 검증.
- 강수확률 정규화(0, 1, 40, 100, null, 잘못된 값).
- 거리 계산 및 좌표 누락 처리.
- 추천 점수 계산 및 결측 데이터 처리.
- 응답 변환기(provider adapter) 테스트.

### API 통합 테스트
- 정상 검색.
- 골프장 데이터 없음.
- 날씨 공급자 timeout.
- 예약 공급자 미연동.
- OpenAI 오류/잘못된 JSON.
- Supabase 연결 오류.
- 부분 실패 시 나머지 데이터 유지.

### UI 수동 테스트
- 데스크톱 1280px, 태블릿 768px, 모바일 360px 및 최소 320px.
- 날짜 선택, 검색 중, 결과, 빈 결과, 오류, 재시도.
- 예약하기 클릭 시 안내만 표시.
- 키보드 탐색과 포커스 표시.
- 브라우저 콘솔 오류 없음.

## 7. 출시 전 체크리스트
- [ ] 모든 API 키는 서버 환경변수에만 존재한다.
- [ ] `.env`가 Git에 올라가지 않는다.
- [ ] 실제 데이터와 샘플 데이터가 명확히 구분된다.
- [ ] 실시간 예약 정보의 출처·조회 시각이 확인된다.
- [ ] 티타임/가격/날씨를 AI가 만들어내지 않는다.
- [ ] 강수확률 null과 예보 기간 밖 상태가 올바르게 표시된다.
- [ ] 거리 종류(직선/도로)가 명시된다.
- [ ] 예약 버튼이 실제 예약 API를 호출하지 않는다.
- [ ] 모바일·접근성 기본 점검을 완료했다.
- [ ] Vercel Preview와 Production 배포를 각각 확인했다.
